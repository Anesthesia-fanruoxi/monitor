## 四、决策与待拍板（汇总）

**当前无阻塞项。** 原先卡住 `workflow/` 各任务的 4 项已于 2026-09-20 全部按建议定稿（见下表 4~7），任何任务都可以直接开工。

> ⚠️ **七项已定，别再翻回来**：
> 1. **兼容复用层不做**（2026-09-20）—— 新架构不与旧系统并存，没有并存窗口就没有复用对象（服务端设计 §5.5）。
> 2. **旧代码不做迁移、也不加测试网**（2026-09-20）—— 只构建新系统。静态定义与旧 `data` 路径**直接删除**，它的性质是新链路的**前置条件**（同名指标在同一个 Registry 里只能注册一次），不是"迁移动作"（服务端设计 §2.2）。
> 3. **制品分发的认证：复用 AES 密钥做 HMAC**（二轮问询即拍板，`插件化架构设计.md §0` 决策表）—— 原列为"待拍板"属漏同步，2026-09-20 移出列表。
> 4. **`heart` 的超时语义：方案 A**（2026-09-20）—— 面板查询改 `absent(is_active{...})` 或 `is_active != 1`，**协议不加 `on_timeout` 字段**（服务端设计 §5.3）。
> 5. **全局序列闸门：加**（2026-09-20）—— `MaxSeriesTotal = 200000` + `MaxSamplesTotalPerReport = 20 万`（服务端设计 §5.4）。
> 6. **启动自检"能连通 service"：默认要求，可显式关掉**（2026-09-20）—— `config.yaml` 的 `allow_offline: true` 时退化为"仅告警并继续"并标注 `offline_mode`（壳契约 §8 第 5 项 + §9 schema）。
> 7. **`k8s` 采集范围：加配置项、默认全量**（2026-09-20）—— `plugins.k8s.namespaces`（空 = 全部）+ `only_with_limits`（默认 `false`）（插件设计 §10）。
>
> 另有 **5 项因会改变指标契约**不做，见本节末尾「本次范围外」。

### 本次范围外（不做，需单独拍板）

下面 5 项**都不在本次承诺内**。共同点是：**会改变已定稿的指标契约**（名字 / 标签 / 取值范围 / 线格式），所以必须单独拍板、单独排期——塞进构建流程会让"构建失败"与"改名失败"无法区分。

| 项 | 内容 | 为什么不在本次范围 |
|---|---|---|
| 标签命名统一 | `hostName` 驼峰 vs `os_version` 蛇形混用 | 改标签名会断面板，且要同步改 `插件设计.md §5` 映射表 |
| `controllerName` 改取 Deployment 名 | 修滚动发布导致的容器指标序列碎片化 | 会改标签值 |
| `cleanNamespace` 去硬编码 | 不再硬剥 `-v1/-v2` 后缀 | 会改标签值 |
| 外部命令依赖替代 | `ss` / `who` / `systemctl` → 读 procfs | 会改取值口径（`/proc/net/tcp` 与 `ss -s` 的聚合口径不完全等价，可能数值跳变） |
| 传输层升级 | protobuf / 密钥版本号 `key_id` / mTLS | 一旦变更所有 agent 要同步升级 |

**"不在本次范围" ≠ "不该做"。** 它们与"构建新系统"是两件事，各自独立立项。

## 五、动代码之前的两条硬约束

1. **指标名只增不改。** 80 个指标名的唯一权威是 `插件设计.md §5`，实现时逐个核对。名字是 Grafana 面板与告警规则的引用键——改名即断图。要改就新增 `xxx_v2`，不改 `xxx` 的含义。**没有兼容层兜底**：静态定义已整体删除，新链路报不出同名指标，那条线就直接消失。
2. **没有 `agent-plugs/` 里的插件，壳什么也采集不到。** 顺序上先有协议与 SDK（`插件化架构设计.md §12` 阶段 0、2），再有壳（阶段 3），最后才是其余插件（阶段 4）。

## 七、落地执行

### 本次范围：只构建新系统（2026-09-20 定稿）

1. **不兼顾旧系统。** 不存在新旧架构并存的窗口——没有灰度、没有兼容层、没有"切换"这个动作。旧 `data` 路径与 80 个静态定义**直接删除**；注意它的性质不是"迁移动作"，而是新链路的**前置条件**（同名指标在同一个 Registry 里只能注册一次，见 §四与 `服务端设计.md §2.2`）。
2. **不给旧代码加保护。** 不为现有实现补测试网；测试只写在新代码上，落在各任务自己的验收里。

由此取消三个任务：安全网与工程门禁（**门禁本身保留为通用规则 5**）、兼容复用层 `compatMetrics`、上线切换与收尾加固（改名等项见 §四「本次范围外」）。

**交付物是一套可运行的新系统，不是"把老系统改造成新系统"。**
