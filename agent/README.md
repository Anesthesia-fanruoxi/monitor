# monitor-agent
## 一、作用
> 差异化采集：心跳/硬件/Nginx 每 15 秒，K8s 容器与控制器每 60 秒，SSL 证书每 5 分钟；数据 JSON → Gzip → AES-GCM 加密后发送到 Server

## 二、已实现功能
+ 基础硬件信息
+ pod信息资源信息
+ 证书监控

## 三、使用
> 由于我是针对我们项目实现编写的监控，所有很多指标不一定可以用，通用的指标如下，只需要配置好，即可使用。
+ hard
+ ssl
+ pod

## 四、可靠性说明
+ **无外部命令依赖（Linux）**：CPU 核心数/型号直读 `/proc/cpuinfo`，内核版本读 `/proc/sys/kernel/osrelease`，磁盘容量走 `statfs` 系统调用。此前依赖 `df` 命令，distroless / scratch 等精简镜像里没有 `df` 会导致整份硬件指标丢失。Nginx 采集仍依赖 `systemctl` / `who` / `ss`，缺失时对应指标为 0 并在日志中告警一次。
+ **主机名获取**：优先 `os.Hostname()`，失败才回退 `/etc/hostname`。此前只读 `/etc/hostname`，容器中该文件常缺失，会连带 heart 与 nginx 两类数据一起丢。
+ **单点失败降级**：硬件采集各字段互相独立，某一项失败只记日志并留空，不再整份丢弃（主机名除外，它是指标标签）。
+ **SSL 探测失败不伪造数据**：探测失败的域名本轮不上报，而不是上报 `days_left=-1`，避免网络抖动被误判为"证书已过期"。
+ **自动更新**：基于 `os.Executable()` 的绝对路径替换，替换前保留 `.bak` 备份；此前写死相对路径 `./agent`，工作目录与二进制目录不一致时会替换到别的文件却把旧二进制重新拉起（更新静默失效）。
+ **守护模式退避**：子进程异常退出按 1s → 60s 指数退避重启；PID 文件只由写入者清理，直接运行 Agent 时也会参与防多开。

## 五、发送数据的时候新增加了压缩功能
> 测试环境数据
+ 压缩前(字节数)

|          | hard | heart | k8s    | k8sController |
| -------- | ---- | ----- | ------ | ------------- |
| 原始数据 | 500  | 145   | 328005 | 125597        |
| 加密大小 | 528  | 173   | 328033 | 125625        |

+ 压缩后(字节数)

|          | hard | heart | k8s    | k8sController |
| -------- | ---- | ----- | ------ | ------------- |
| 原始数据 | 506  | 145   | 327989 | 125597        |
| 压缩大小 | 304  | 136   | 25609  | 4318          |
| 加密大小 | 332  | 164   | 25637  | 4346          |
| 比例变化 | 0.34 | -0.13 | 0.92   | 0.97          |

由于压缩原理导致数据比较小的会增大，数据比较大的压缩比很高。
