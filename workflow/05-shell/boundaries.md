# 05 agent 壳 — 边界

## 做什么

- 配置（三键 + 三级取值 + 钳制 + 热加载）
- 契约 8 条不变式（I1~I8）
- 插件监管（懒下载 / 原子替换 / 回滚 / 硬超时 kill / 熔断）
- 调度器（周期 + 相位打散 + 单在途请求）
- 传输与上报（加解密只在壳里做一次）
- 心跳（留在壳内）
- 只读状态端点（唯一有界面的部分，见 `ui.md`）
- 失败域隔离 + 启动自检 + 行数预算

## 不做什么

- **不做任何远程控制。** 没有"服务端下发指令让某台 agent 停用某插件"这种能力。代价是批量改启用要触达每台机器（需 Ansible 之类），换来壳里零远程控制代码。
- **不新增第 5 类输入。** 壳的输入恒为四类：`config.yaml` / 插件 stdout 信封 / 进程状态 / service 的四类响应。
- **壳不解析指标内容。** 只测长度、算 sha256（可选），`Metrics` 永不 `Unmarshal`。
- **不把业务知识写进壳。** 心跳是唯一例外（它有明确理由：插件可被停用）。
- **不做插件间的依赖编排**（明确不支持）。
- **不做壳的自更新。** 更新交给 systemd / 容器编排（物理机换二进制 + `systemctl restart`，容器换镜像 tag）。`docs/壳设计.md §十一` 已整节改写。
- **不做协议兼容层。** 协议只有 v1，不存在要兼容的旧版本；`proto > 1` 显式拒绝。
- 不实现插件（04、06）；不改 service（02）。旧 `UnRegister*.go` / `HanderData.go` / 静态定义已在 02 删除，本任务不回头碰。

## 红线

- **壳只有一份代码，1000+ 台要动二进制。** 任何让壳变复杂的改动都要先问："这个字段能不能从 `config.yaml` / `manifest.yaml` 拿到？"能，就不该进信封（契约 §2.5）。
- **依赖白名单：stdlib + `gopkg.in/yaml.v3`。** 除自身与 `plugproto` 外不得出现其它依赖。
- **写盘清单固定**：`agent.pid`、`agent-plugs/`。不落业务状态——没有队列文件、没有"上次成功时间"、没有"待重试列表"、没有"已装版本清单"（已装版本直接读 `manifest.yaml`）。**重启即自愈，无"残留状态"类疑难 bug。**
- **顶层配置非法值只告警并保留旧值**，绝不因配置写错导致全网上报失败。
- **`proto > 1` 显式拒绝**，不静默降级。
- 不提交真实 AES 密钥；`config.yaml` 与 `server/config/` 保持 gitignore。

## 最大风险与对策

| 风险 | 对策 |
|---|---|
| 壳里出现必须修的缺陷，1000+ 台要动二进制 | 壳不自更新（`壳设计.md §十一`），更新由 systemd / 容器编排负责：物理机换二进制 + `systemctl restart`，容器换镜像 tag 滚动更新 |
| 壳"启动后半死"（进程活着但不干活） | 启动自检，任一不过直接退出，交给 systemd `Restart=always` 或容器重启策略（S9） |
| 插件演化改了协议字段名 | 契约 §3.5 冻结边界表 + `proto` 协商 + 显式拒绝不认识的高版本 |
