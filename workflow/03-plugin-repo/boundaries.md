# 03 插件制品仓库 — 边界

## 做什么

- 制品打包（`build.sh` + `dist/`）
- `index.json` 生成（全平台）
- 下载端点 + HMAC 签名校验
- 划清边界：只服务**插件**制品（壳不进制品体系）
- service 镜像打包

## 不做什么

- **不做远程管理。** **插件**的版本由配置 + 制品清单驱动（壳的版本由 systemd / 容器编排驱动，不经制品清单），不做"推送指令到某台机器"的控制面。这是刻意的取舍：换来壳里零远程控制代码。批量改插件启用要靠 Ansible 之类外部工具。
- **不给 agent 自己做分发。** 壳不自更新（`docs/插件化架构设计.md §2.4 §5.6`），所以这里不做"把 agent 当特殊制品"那一套。
- 不签名证书体系、不上 mTLS（属**范围外待拍板项**，见 `docs/README.md §四「本次范围外」`）。
- 不做 CDN / 分片下载 / 断点续传——1500 台的量级用"0~30s 抖动 + 仅版本变化时下载"就够。
- 不实现 agent 侧的下载逻辑（那是 05）。

## 红线

- **`update.ipPass` 与 `ipPass` 保持解耦。** 它现在只用于**插件制品下载**；未配置 `update.ipPass` 时才回退 `ipPass`。合并两者会让"允许抓指标"隐含"允许下载制品"，是权限放大。
- 制品校验值（sha256）必须由 service 提供并与包一并校验；不接受"下载了就用"。
- 不引入新的凭据体系（复用 AES 密钥做 HMAC）。
- 不动生产环境；只在测试节点验。

## 产出物

| 文件 | 内容 |
|---|---|
| `agent-plugs/build.sh` | 交叉编译 + 打包 + 生成 `index.json` |
| `dist/<name>-<ver>-<os>-<arch>.tgz` | 制品包 |
| `index.json` | 制品清单（全平台） |
| 下载 handler + HMAC 校验 | service 侧 |
| `pluginrepo` 单测 | 签名正误 / 过期 / 重放 / 穿越 |

## 依赖

- 上：01、02、04（**制品内容来自 04 的 `hard` 插件**——没有它就没有可打包的东西。S3~S5 可与 04 并行，S1 / S2 的验收须等 04 完成后回归一次）
- 下：05（壳的懒下载依赖本任务的 `index.json` 与下载端点）

## 已知风险

- **1500 台同时拉取插件**会让 service 带宽与 IO 出现尖峰 → 下载侧加 0~30s 抖动 + 只在下发版本变化时下载。
- agent 容器内无写权限会导致下载失败 → 部署文档必须明确要求挂载可写卷（`emptyDir` 或 hostPath）。
