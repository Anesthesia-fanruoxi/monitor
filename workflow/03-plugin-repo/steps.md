# 03 插件制品仓库（service 侧） — 步骤

> 目标：service 能按平台分发插件制品包，agent（05）能懒下载并校验。
> 前置：01、02、**04**——本任务打包的对象是 04 产出的插件制品；在 04 完成前 S3~S5 可与它并行，但 **S1 / S2 的验收必须在 04 完成后再跑一次**（没有真实制品就没有可打包、可入清单的东西）。
> 参考：`docs/服务端设计.md §7`（制品布局、`index.json`、下载认证）、`docs/插件设计.md §七`（build.sh / 生成 index.json / 发布）、`docs/插件化架构设计.md §五 §5.6`
> 已定（无需再确认）：制品分发的认证**复用 AES 密钥做 HMAC**——`docs/插件化架构设计.md §0` 二轮问询拍板表 + `docs/服务端设计.md §7.3`（完整实现：时间窗 + nonce 去重 + 签名 + `update.ipass` 白名单 + sha256）

---

## 步骤

### S1 制品打包（镜像内布局）

- **动作**：按 `§7.1` 布局落制品，走 `agent-plugs/build.sh` 交叉编译 + 打包。
- **整包分发，不允许只发二进制**——否则会出现"新二进制配旧默认配置"的版本错配。
- 包内容（`docs/插件设计.md §2.2`）：
  ```
  hard-1.2.0-linux-amd64.tgz
  ├── hard                # 二进制
  ├── default.yaml        # 默认配置（升级时随包覆盖）
  └── manifest.yaml       # 名称/版本/平台/入口/协议版本/min_agent_version
  ```
- **产出**：`agent-plugs/build.sh` + `dist/`
- **验收**：`dist/` 下每个插件都有 amd64 与 arm64 两包，包内三件齐全。

### S2 `index.json` 生成（§7.2）

- **动作**：生成制品清单，**必须列全平台**——否则 arm64 机器拿不到插件。
- **验收**：`index.json` 与 `dist/` 内容一致；手动删除一个包再重新生成，清单同步减少；找一台 arm64（或伪造平台查询）能查到对应条目。
- **坑**：agent 找不到自己平台时，行为必须是"保持旧版本并明确告警"，不能静默跳过（这条属 05 的实现，但契约在这里定）。

### S3 下载端点 + HMAC 签名校验（§7.3）

- **动作**：复用 AES 密钥做 HMAC，不引入证书体系（与现状一致）。
- **验收**：
  - 手工 `curl` 能下载到制品并校验 sha256 一致；
  - 签名错误 → 拒绝；
  - 签名过期 → 拒绝；
  - nonce 重放 → 拒绝；
  - 路径穿越（`../`）→ 拒绝。
- **产出**：下载 handler + `pluginrepo` 单测（`§12.1` 表最后一行）。

### S4 划清边界：制品仓库只服务插件

- **动作**：**壳不自更新**（更新交给 systemd / 容器编排，见 `docs/插件化架构设计.md §2.4`），因此制品仓库**只服务插件制品**，不需要"把 agent 当特殊制品分发"。
- **验收**：新壳代码里搜不到 `/version`、`/agent/agent`、`/agent/agent.sha256` 的引用；`update.ipPass` 只用于插件制品下载。
- **红线**：**不得把两个白名单合并**。制品下载端点与 metrics 端点白名单解耦是既有安全基线。

### S5 更新 service 镜像与部署说明

- **动作**：制品随镜像发布（`§十一 Docker 打包`），说明可在容器里通过挂载或内置方式提供。
- **验收**：从镜像里 `curl` 下载端点拿到完整制品包。

## 退出条件

- [ ] `index.json` 与 `dist/` 一致且全平台列齐
- [ ] 手工 `curl` 能下载 + 校验 sha256；四类非法请求（错签/过期/重放/穿越）全被拒
- [ ] 新壳不再引用任何 agent 自更新端点；两个白名单保持解耦
- [ ] 通用规则 5 的门禁全过
