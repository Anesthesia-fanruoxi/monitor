# monitor 长任务工作流

> 通用规则在上，任务列表在下；每个任务的详细规划见各自目录的 `steps.md`（步骤）/ `boundaries.md`（边界）/ `ui.md`（UI 设计）。
> 流程：步骤完成 → 按验收标准验收 → 标记 `[x]`。
> 开工前先读 `docs/README.md`（文档地图）：**§四 待拍板事项**（**当前无阻塞项**——原先卡任务的 4 项已于 2026-09-20 定稿）、**§六 验证基线**、**§七 本次范围**。
> 任务顺序：`01 → 02` 与 `01 → 04` 两条并行，汇到 `03 → 05 → 06`。**04 必须先于 03**（03 打包的对象是 04 产出的插件）。**不能反**——没有协议与 SDK 就没有壳，没有插件壳什么也采集不到。

## 通用规则

1. 代码文件单个不超过 300 行，超出须拆分（文档除外）。
2. 长任务流程：先在任务目录写 `steps.md`（步骤）+ `boundaries.md`（边界）+ `ui.md`（UI 设计）→ 用户确认后开始执行 → 各步骤依次执行不再逐步确认 → 每步完成后验收并标记完成 → 超出 scope 时暂停询问。
   - 本项目**只有壳的只读状态端点有界面**（`05-shell/ui.md`）；其余任务是纯后端 / 工具 / 文档，**不建 `ui.md`**。
3. 每次验收完成后必须立即修改 `workflow.md` 将对应步骤标记 `[x]`，不得遗漏。
4. 开始长任务前先读 `workflow.md`，据此创建任务清单（TodoList）并在执行中同步实时更新。
5. 改动须编译通过：两端各自 `go build ./...`；交叉编译 `CGO_ENABLED=0 GOOS=linux GOARCH=amd64 go build ./...`（**Windows 上必做**）；`go vet ./...` 与 `gofmt -l .` 干净；`go test ./...` 通过。部署仅替换测试节点并保留旧二进制备回退。
6. 红线：不动生产环境；不提交密钥凭据；不未经确认删除文件或重置数据；不改 scope 目标外的模块。
7. 修改完成后总结改动内容与效果；踩坑与决策记入对应任务目录的 `spec.md`（**开工时创建**；记录：时间 / 改动 / 效果 / 踩坑 / 决策）。
8. **指标名只增不改。** 80 个指标名以 `docs/插件设计.md §5` 为唯一权威，改名即断图（`docs/服务端设计.md §5.6`）。**没有兼容层兜底**——静态定义已整体删除，报不出同名指标那条线就直接消失。
9. **壳的契约只能走评审。** 壳对插件输出的认知恒为 **4 个字段 / 8 条不变式 / 1 个文件**（`agent/internal/proto`）。想让壳多认识一个字段，先过 `docs/壳契约-v1.md §2.5`，再走 §12 的评审清单。
10. **验收标准必须可执行。** 每条验收要能落成一条命令、一个断言或一次明确的人工核查。写不成可执行验收的，说明这步还没拆到位，先回去拆。
