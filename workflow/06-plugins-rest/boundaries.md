# 06 其余插件 — 边界

## 做什么

- `nginx` 插件（13 指标）
- `ssl` 插件（1 指标）
- `k8s` 插件（11 指标，原 `k8sContainer` + `k8sController` 合并）
- 指标契约对齐验证（逐字）

## 不做什么

- **不改任何指标名、标签名、标签集合。** 通用规则 8。`docs/插件设计.md §5` 是唯一权威，实现时逐个核对。
- **不"顺手修"历史遗留**：
  - `memory_*` 单位 kB（`hard` 插件，04 已定）——不改；
  - `controllerName` 取 ReplicaSet 名——不改（属**范围外**）；
  - `cleanNamespace` 硬编码剥 `-v1/-v2`——不改（属**范围外**）；
  - 标签命名驼峰/蛇形混用——不改（属**范围外**）；
  - `agent_version` 用 float——不改；
  - 外部命令依赖（`ss`/`who`/`systemctl`）——不改（属**范围外**）。

  范围外各项见 `docs/README.md §四「本次范围外」`。**理由不是"没时间"，而是它们都会改指标契约**：名字与标签是面板与告警的引用键，改了就断图。构建新系统与调整契约是两件事，混做会让失败无法归因。
- **不给 `heart` 做插件**。心跳留在壳内（05 已实现）——否则"用户停用了 heart 插件"与"主机真的离线了"在服务端看来完全一样。
- **不给 `trafficSwitching` 做插件**。它由流量切换平台直连 `POST /metrics_data`，原来就不装在机器上；平台侧照服务端提供的「36 个指标声明模板」填值即可。
- 不实现插件间依赖（明确不支持）。`k8s` 两个采集器合并正是因为**声明式协议的 `metrics` 本来就是数组，一个插件声明多组指标零损失**。
- 不改壳（05）、不改 service（02）。

## 红线

- **逐字核对指标名与标签。** 建议做法：把 `docs/插件设计.md §5` 的映射表与插件代码并排对照，一条一条打勾。**这一张表是本次重构最关键的东西**——静态定义在 02 已被删除，映射表是 80 个指标名的唯一权威。
- **`ssl` 探测失败的域名不上报，不要填 `-1`。** 填 `-1` 会在面板上造出"证书已过期"的假告警。
- **`nginx` 缺命令不要让整个插件失败。** 上报 0 + warn-once 是现状行为。
- **`lastTerminationTime` 用分钟**，与现有 Help 一致（注释写"秒"是实现与注释不一致，以 Help 与实现为准）。
- 不动生产环境；逐个插件在测试节点验证。

## 最容易出错的三处（历史踩过的坑）

1. `tcpTotal` ↔ `nginx_tcp_total` / `totaltcp` ↔ `nginx_total_tcp` —— **词序交叉**，曾经写错过。
2. `cpu_count`（agent 字段）↔ `cpu_total`（指标名）—— 不同名。
3. `lastTerminationTime` 单位是分钟，不是注释里写的秒。
